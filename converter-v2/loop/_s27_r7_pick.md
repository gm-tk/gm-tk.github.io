## Session 27 — Round 7 PICK (in progress; 19 Sept ≈13:45 NZST): the `[interactive: X]` bracket's `activity` alias must not make the preceding media line a widget's OWNER

- **The class (recorded at the r401 ship, AGH1005 lesson 2):** `[interactive: video]` / `[interactive: image]` / `[Interactive video]` parse to `primary = video / ELEMENT` with a second tag `activity` whose alias word is `interactive` (`_s27_r5_parse1.cjs`). `InteractiveScanner`'s owner lookback (`prev.parse.tags.some(t => t.tag === "activity")`) takes ANY span carrying an `activity` tag as the following widget's activity OWNER — so the writer's video line before `[interactive: drag and drop]` becomes the drag-and-drop's owner: the video never renders (the gold's `videoSection` is missing from Claude's page), the box opens with no title and (the bundle having captured nothing) holds only the `no content captured` flag.
- **To measure first (`_s27_r7_ownerscan.cjs`, the live scanner over all 416 modules):** every bundle whose `activityOwner`'s PRIMARY tag is not `activity` — by primary tag / directive and by the activity tag's alias word — and, for each, what the gold ships at that spot (a `videoSection` / `img` before the box, the box itself). The fix, if the population holds: the lookback accepts a span as the owner only when its activity tag is the span's primary or a bare / numbered `[Activity …]` form (a data list of the alias words that never open an activity — `interactive` — in `Interactive_Boundary_ChildTag_Bank._meta.opener_rule`), env `OWNERALIAS_OFF`; the media line then renders through the normal element path and the widget takes the r217 / r401 standalone form.
- **Gate expectation:** the media element restored on the affected pages (a `videoSection` / `img` line the gold has), the owner box replaced by the standalone box where the bundle has content or by the bare flag where it has none; scored on the probe's ON pages before regenerating.
